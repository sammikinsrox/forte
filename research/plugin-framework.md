# Plugin framework: JUCE/C++ vs nih-plug/Rust (and others)

Research for ticket [0004](../issues/0004-plugin-framework-comparison.md). Sources were checked on 2026-11-14. Each claim links to the source it came from.

## TL;DR (plain language)

**Use JUCE 9 (C++) under its free AGPLv3 licence. Build with CMake and output VST3 plus Standalone.** For the editor, lean towards JUCE's **WebView UI** (the interface is drawn with HTML/CSS/JavaScript inside the plugin window). Native JUCE graphics (GPU-backed Direct2D) is the fallback. Settle that UI choice with a short prototype before committing.

Why, in one paragraph: JUCE is the industry-standard toolkit. It is actively released (9.0.5 shipped 2 Nov 2026), it is heavily documented, and almost every commercial plugin you have used was probably built with it. Its free licence is legally compatible with Forte's GPLv3. It has the highest ceiling for a beautiful, animated, bespoke editor. Rust (nih-plug) would give the AI-written code better compiler-enforced safety. But the original nih-plug is now in maintenance mode. Its successor fork, nice-plug, calls itself "experimental" and is still making large editor-API changes. Rust GUI options are also clearly weaker for the "beautiful custom UI" requirement. C++'s safety gap can be narrowed with tooling (automated plugin validation, sanitizers, strict rules for the audio thread, and tests). Rust's UI and maturity gap can't be closed from our side.

## What changed recently (don't trust older advice)

- **VST3 SDK is now MIT-licensed (since 3.8, October 2025).** Steinberg says: "Since version 3.8, VST 3 is licensed under MIT license". The GPLv3 and proprietary options are "no longer available". You don't need to sign anything or pay fees. Using the VST name or logo is optional, and if you use it you must follow Steinberg's trademark guidelines. ([Steinberg VST 3 License](https://steinbergmedia.github.io/vst3_dev_portal/pages/VST+3+Licensing/VST3+License), [vst3sdk repo](https://github.com/steinbergmedia/vst3sdk), [Steinberg 3.8.0 release post](https://forums.steinberg.net/t/vst-3-8-0-sdk-released/1011988)). **Effect:** the VST3 licence is no longer a deciding factor for any framework. MIT is GPL-compatible.
- **JUCE 9 is out.** 9.0.0 shipped 21 Jul 2026 and the latest is 9.0.5 (2 Nov 2026). It brings a new SVG parser, variable fonts, a faster software renderer, Direct2D fixes, and a TypeScript npm package for WebView UIs (9.0.1). ([JUCE releases](https://github.com/juce-framework/JUCE/releases)). The licence tiers and EULA are unchanged from JUCE 8 ([JUCE forum, 17 Jun 2026](https://forum.juce.com/t/juce-9-no-pricing-or-eula-changes/69000)).
- **nih-plug is in maintenance mode.** The README says: "`NIH-plug` the plugin framework is currently in maintenance mode", and it points to a community fork ([nih-plug README](https://github.com/robbert-vdh/nih-plug)). The last substantive commits were in May 2026 ([commits](https://github.com/robbert-vdh/nih-plug/commits/master)). The fork has become **nice-plug** (latest 0.4.2, 14 Sep 2026). Its README says: "This project is currently experimental, and has recently undergone some large changes, so expect some bugs." ([docs.rs nice-plug](https://docs.rs/crate/nice-plug/latest), [Codeberg repo](https://codeberg.org/BillyDM/nih-plug)).

## Recommendation, explained for a non-programmer

1. **Framework: JUCE 9, AGPLv3 licence, CMake build, VST3 + Standalone targets.**
   - *Licence:* it's free, and the AGPL licence can legally be combined with GPLv3 Forte. We have to publish source, which we're doing anyway. The VST3 part is MIT now, so there's no Steinberg paperwork.
   - *Hosts:* JUCE plugins run in FL Studio and Reaper every day. When a host quirk turns up, someone on the JUCE forum has usually already solved it.
   - *Beauty:* JUCE has two strong routes to a bespoke, animated editor (below). Rust's GUI options are the weakest part of that ecosystem today.
   - *Safety:* Rust's main selling point is that the compiler stops many bugs. We'll get much of that protection from process instead: automatic plugin validation (pluginval) on every build, strict "no allocating on the audio thread" rules with tests that check them, and DSP unit tests compared against reference numbers.

2. **Editor technology: prototype before deciding.** Two candidates are both inside JUCE:
   - **WebView UI (leaning towards this one).** The editor is a small web page inside the plugin window. It gets the richest design and animation tools (CSS, SVG, canvas/WebGL) and the AI writes it very fluently. You can also preview it in a normal browser. Risks: it depends on Windows' WebView2 runtime (built into Windows 11, and most Windows 10 machines have it), it uses more memory, and the "best practice" is still young ([JUCE WebView overview](https://juce.com/blog/juce-8-feature-overview-webview-uis/)).
   - **Native JUCE graphics** (Direct2D GPU rendering, the `juce_animation` module, SVG, variable fonts). It's lighter and has no runtime dependency, but polished animation takes more hand-built code.

3. **Rust/nice-plug: not for v1.** Revisit it if nice-plug stabilises (a 1.0 release and documented GUI story). Its safety model is genuinely attractive for an AI-written codebase, but right now the framework is "experimental" and in the middle of API changes.

## Open questions surfaced (candidate tickets)

- **Editor rendering approach:** a prototype ticket comparing a JUCE WebView editor with a native JUCE (Direct2D) editor. Check look, animation smoothness, CPU/GPU cost, and behaviour in FL Studio and Reaper (resizing, HiDPI, keyboard focus, and the WebView2 user-data folder).
- **Real-time safety guardrails for C++ on Windows:** how to detect audio-thread allocations and locks in our tests, since RTSan isn't documented for Windows. Options include a custom allocator hook in tests, Linux CI with RTSan, and pluginval strictness level.
- **Build toolchain:** MSVC or clang-cl, and the CMake layout (JUCE through `add_subdirectory` or as a git submodule). This could fold into the existing "Build, installer and release" item.
- **VST trademark/logo use:** whether to show the VST logo, which would mean following Steinberg's usage guidelines.
